# 地图重建 V6：逻辑格网优先，截图只提供观测证据

## 结论

停止把“小地图截图”当作一张需要擦除图标、补回线条的图片。新的核心产物是一个
离散地图：每个菱形格子保存状态、置信度、观测次数和来源。道路图只是从离散地图
重新渲染出来的视图。

优先级如下：

1. 从游戏运行时取得地图格子/房间数据；
2. 若暂时拿不到运行时数据，按游戏自身的等距坐标公式对截图做固定格点采样；
3. 图标识别仅用于标注物体和把被遮挡格设为 `UNKNOWN`，不再用于修补道路像素。

## 已从 APK 确认的几何

`libcocos2dlua.so` 中的 `Avalon::MapGrid` 使用固定单元尺寸 `44 × 22`：

```text
screenX = originX + (gridX - gridY) * 44 / 2
screenY = originY + (gridX + gridY) * 22 / 2
```

反变换为：

```text
a = (screenX - originX) / 22
b = (screenY - originY) / 11
gridX = (a + b) / 2
gridY = (b - a) / 2
```

游戏的 `MapGrid::parse` 也不是沿轮廓追踪。它遍历格子，调用上述坐标变换，在每个
格子的固定位置读取像素，并输出字符 `0/1` 网格。这证明“固定格点分类”比“边线补洞”
更接近游戏原始设计。

小地图显示时允许整体缩放，因此截图里的基向量写成：

```text
rightDown = scale * (22, 11)
rightUp   = scale * (22,-11)
```

`scale` 和 `origin` 每帧标定，但格子比例始终保持 2:1。

## 数据模型

每个逻辑格保存：

```text
UNKNOWN       从未可靠观察，或被图标/迷雾遮挡
WALKABLE      已确认道路内部
BLOCKED       已确认非道路
FRONTIER      WALKABLE 邻接 UNKNOWN，必须继续探索
```

附加字段：

```text
walkVotes, blockVotes, observations, lastFrame,
confidence, iconType, worldObjectId
```

`UNKNOWN` 与 `BLOCKED` 必须严格区分。未探索区域不能因为颜色像背景就被判为墙；只有
在它进入可靠可见范围、且多点采样一致时，才能转为 `BLOCKED`。

## 单帧处理

1. 识别玩家蓝色标记的落地点（尖端），而不是包围框中心。
2. 使用稳定的长道路边和 2:1 约束估计 `scale`、旋转和格网相位。
3. 将玩家落地点吸附到最近格点，并暂定该格为本帧 `(0,0)`。
4. 在每个格子内部使用多个偏移采样点，不采图标中心，也不追踪边线：
   - 内圈道路色比例；
   - 两条菱形轴上的一致性；
   - 与相邻格之间是否存在连续道路色；
   - 是否被已知图标透明轮廓覆盖。
5. 被图标覆盖的格只记录 `UNKNOWN + OCCLUDED`，绝不补画。

## 多帧拼接

地图坐标不再由截图左上角决定，而由玩家逻辑格和格网变换决定。

```text
globalCell = frameCell + framePlayerGlobalCell - framePlayerLocalCell
```

玩家移动后的新帧先根据可见道路格做整数格平移配准，再用玩家移动方向解决候选平移
并列。只允许整数格变换；不会产生逐帧累积的亚像素漂移。

融合规则：

- 新帧的高置信 `WALKABLE` 可以增加通行票数；
- `BLOCKED` 必须至少两次无遮挡观测，且不能覆盖既有高置信 `WALKABLE`；
- 图标遮挡不给任何通行/阻塞票；
- 冲突格保留两类票数并显示为待复核，不用形态学闭运算强行连通；
- 最终道路边线由相邻格状态生成，不从截图中恢复。

## 探索策略

从玩家所在的已确认连通分量计算所有 `FRONTIER`。目标选择按以下顺序：

1. 可达且距离最近；
2. 周围 `UNKNOWN` 数量更多；
3. 避免连续选择最近失败过的边界；
4. 到达后重新截图并融合，直到不存在可达 `FRONTIER`。

这样迷雾遮住的地方始终是 `UNKNOWN/FRONTIER`，不会因为图像边界被模糊或填色而丢失。

## 两条实现路径

### A. 运行时数据路径（首选）

继续解密 `MiniMap.luac`、`MiniMapDrawer.luac`、`MapGrid.luac`，定位传给绘制层的格子、
房间和探索状态表；或在调试设备上只读记录这些 Lua 调用参数。若能拿到该表，可完全
跳过道路视觉识别，截图只用于验证和识别玩家当前显示状态。

### B. 游戏几何约束的视觉路径（可立即实现）

复用 APK 已确认的 `44×22` 坐标关系，自动标定截图缩放，输出离散格网及置信度。
第 3、4 张图中人物不动，因此两帧必须落到同一全局格，只增加观测证据，不允许产生
人物位移。

## 验收输出

Windows 工作台应同时显示：

1. 原始截图与格点采样位置；
2. 单帧 `WALKABLE/BLOCKED/UNKNOWN/OCCLUDED` 分类；
3. 每帧整数格配准和玩家局部/全局坐标；
4. 累计逻辑地图；
5. 当前连通分量、探索边界和下一个目标；
6. 冲突格及每格票数，方便定位误判来源。

旧的图标擦除和像素补线结果只作为实验对照，不进入 V6 地图状态。
