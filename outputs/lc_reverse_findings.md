# script.lc 逆向结果（校正版）

## 结论

`assets/script.lc` 不是自定义指令虚拟机文件，而是一个 Protocol Buffers 风格的容器。容器内保存了变量/符号表，以及三个经过逐字节变换的 Lua 5.2 字节码块。

还原后的三个代码块均以以下标准 Lua 5.2 头开始：

```text
1B 4C 75 61 52 00 01 04 04 04 08 00 19 93 0D 0A 1A 0A
```

其中 `1B 4C 75 61` 是 `\x1bLua`，`52` 表示 Lua 5.2。

## 容器结构

顶层可确认的字段包括：

- field 1：编译时间字符串 `Jun 17 2021 15:13:53`
- field 2：大量数值/行号类数据
- field 3：主代码块之一，1,055,409 字节
- field 5：326 项变量或符号名映射
- field 6：命名模块容器；本样本模块名为 `f`，代码 917,916 字节
- field 7：入口代码块，2,283 字节

符号表直接包含 `地图坐标连接`、`找角色`、`角色位置:移动X/Y`、`起点位置`、`终点位置` 等名称，因此地图逻辑确实位于这些 Lua 字节码块中。

## 原生加载流程

`libmqm.so` 的执行链如下：

1. JNI `Run` 包装函数进入 `FUN_00053c18`。
2. `FUN_00053c18` 打开并解析 `.lc` 容器。
3. `FUN_000538c4` 初始化 Lua 运行时并调用 `FUN_00053548` 装载代码块。
4. `FUN_00053548` 对每个代码块调用 `FUN_0004ecb0`，随后还原字节并调用 Lua load/pcall。

`FUN_0004ecb0` 会从偏移 `0x12` 开始、每隔 3 字节与 64 位 key 的循环字节异或。本 APK 的 Java 配置中 `encryptKey=0`，所以该异或阶段不改变数据。之后程序对所有既非 `00` 也非 `FF` 的字节按位取反。

等价还原式：

```text
decoded = encoded                         当 encoded 为 00 或 FF
decoded = FF - encoded                    其他情况
```

## 已导出的文件

- `lc_chunks/module_primary.luac`
- `lc_chunks/module_f.luac`
- `lc_chunks/module_main.luac`

这些文件可以继续交给支持 Lua 5.2 的反编译器。由于 Lua 字节码保留了大量函数名、字符串及局部符号，下一阶段可重点定位 `找角色`、`地图坐标连接`、`角色位置` 和 `找路` 对应的函数原型与指令。

## 地址说明

ELF 虚拟地址与 Ghidra 工程加载地址相差 `0x10000`。本报告采用 Ghidra 地址；此前把 Capstone 地址直接当作 Ghidra 地址会落到错误函数，现已校正。
