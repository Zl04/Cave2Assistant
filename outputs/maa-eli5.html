把 MAA 想成一支会玩游戏的机器人

MAA = 明日方舟助手。它不是一个“神奇按钮”，而是一套把机器人拆成眼睛、手、脑子和工作清单的系统。

我们要借鉴的是“分工方式”，不是整台机器人。

“刷图、领奖、回城”

→
🤖

自动化大脑

判断现在画面是什么，再决定下一步。

→
🎮

游戏

截图、点击、滑动、等待结果。

三、Pipeline 到底是什么？

Pipeline 就是一张“如果看到 A，就做 B；成功走 C；失败走 D”的流程图。

1看到传送门？
→
2走到旁边
→
3点击传送门
→
4等待弹窗
→
5选择加成
如果没有看到弹窗：等一会儿再看；超过次数还没有看到：释放触摸并安全停止。

MAA 的官方 Pipeline 还规定了识别顺序、轮询间隔、超时、错误分支、画面稳定等待和点击目标。[查看官方 Pipeline 协议](https://github.com/MaaXYZ/MaaFramework/blob/main/docs/en_us/3.1-PipelineProtocol.md)

四、如果移动中突然弹窗呢？

这时不能等走完再处理。要安排一个“值班员”一直看着屏幕。

🏃

移动员

按照路线持续走路。

👮

弹窗值班员

移动期间持续检查：有没有弹窗、战斗或异常遮罩？

1移动中发现弹窗
→
2立刻取消移动
→
3先松开触摸
→
4处理弹窗
→
5重新看地图再继续
值班员只能发出“暂停请求”，不能和移动员同时乱点屏幕；所有点击、滑动、松手都要经过同一个“交通警察”。

所以这里的重点不是两个线程抢着操作，而是“一个负责观察，一个统一负责操作”。

五、当前项目和 MAA 的关系

当前项目已经有

地图快照、楼层状态机、地图寻路、路线执行、偏移/停滞恢复、Lua 状态、ADB 和 OCR。

≈

机器人已经有脑子和腿

尤其是地图规划和移动控制，不需要推倒重来。

现在比较挤在一起

窗口 UI、弹窗识别、换层选择、路线循环和停止清理都在 MainForm 里。

→

应该补一个“小秘书”

专门管理弹窗和 UI 流程，叫 OverlayPipelineRunner。

六、最简单的改造方案

1

保留原来的地图大脑

Planner 继续规划去哪儿，RouteExecutor 继续负责怎么走。

2

把弹窗交给小秘书

秘境选卡、换层确认、战利品确认、服务器异常，先从这四类开始。

3

每一步都留下结果

记录：看到了什么、点了哪里、成功了吗、重试了几次。

4

失败时先松手

识别失败、状态不可信或设备异常时，先释放触摸，再决定重试还是停止。

七、哪些要借鉴，哪些不要？

✅ 借鉴

任务清单、识别和动作分开、失败分支、重试上限、事件日志、资源独立更新。

❌ 暂时不借鉴

整套 C++ 框架、复杂任务表达式、把地图规划改成 JSON、全屏高频 OCR、早期远程控制。

一句话记忆

现在的项目已经会“看地图、想路线、控制人物”；下一步只需要把“看弹窗、点按钮、失败恢复”单独整理出来。
