# 地图导航逆向：第二阶段结果

## 已完成

三个 Lua 5.2 字节码块已经使用 unluac 1.2.3 拆解为函数、常量、局部变量、源码行号和指令清单：

- `module_primary_disassembly.txt`
- `module_f_disassembly.txt`
- `module_main_disassembly.txt`

按键精灵对 Lua 5.2 的 opcode 编号做了重排。因此 unluac 能正确读取函数树、字符串、局部变量和行号，但把指令名按标准 Lua opcode 解释后会出现错误，暂时不能直接生成可信 Lua 源码。下一步需要从 `libmqm.so` 恢复 opcode 映射表。

## 地图坐标连接

已精确定位到 `module_f` 的 `main/f449`：

- 原始源码行：25962–26000
- 参数数量：3
- 参数：`起点`、`终点`、`是否反数据`
- 局部数据：`查找列表`、`路线`、`找过`
- 其他局部变量：`C`、`I`、`ZD`、`ZG`、`B`、`L`、`D`
- 使用的库函数：`LuaAuxLib.NewArray`、`LuaAuxLib.TableSize`
- 坐标节点的字符串形式：`0-0`
- 坐标分隔符：`-`

这表明它不是直接在像素上寻路，而是在已经生成的二维地图/连通图上搜索：

1. 起点、终点作为两个输入节点。
2. 建立待查列表、当前路线和已访问集合。
3. 节点以 `X-Y` 字符串保存。
4. 循环扩展相邻节点并避免重复访问。
5. `是否反数据` 很可能控制输出路线方向或图数据方向。

从局部变量生命周期和循环结构判断，这是队列/列表式图搜索，接近 BFS/DFS，而不是 A*（当前函数中没有发现权重、代价或启发式距离常量）。

## 角色位置

已定位 `module_primary` 的 `main/f297`：

- 原始源码行：23234–23347
- 局部变量：`角色位置:看小图数`、`角色位置:移动X`、`角色位置:移动Y`、`角色位置:首领激活`
- 读取 `0.txt`
- 读取或写入 `路径`、`有方向`、`居中`、`看小图数` 等共享变量
- 使用 `KeepReleaseScreenSnapshot` 保存/释放截图
- 使用 `TouchOperation`、`Tap` 和 `Sleep` 驱动人物移动
- 读取 `终点X`、`终点Y` 和 `方向数组`
- 使用 `找角色`、`清空数组`、`找过`、`待找路X/Y`、`存入起点`
- 异常分支包含“有门无路，尝试找路”“关闭小地图”“不是快速下楼点灵视”

由此可还原高层流程：

```text
打开/保持小地图截图
        ↓
找角色，得到当前小地图中的人物坐标
        ↓
读取当前层地图数据（0.txt 等）与目标坐标
        ↓
把当前坐标存为寻路起点
        ↓
调用地图坐标连接生成路线/方向数组
        ↓
按方向执行触控移动
        ↓
再次截图、重新找角色并校正偏差
        ↓
遇到门、换层或无路时重建路线
```

## 找路与找角色

`找路` 函数已定位在 `module_primary` 约 69625 行附近，局部变量包括：

- `找路:距离X`
- `找路:距离Y`
- `找路:杀完BOSS`
- `找路:I`
- `找路:是否相等`
- `找路:RCOLOR`

说明道路判断至少结合 X/Y 距离与颜色值 `RCOLOR`，并有 Boss 清理后的特殊路径状态。

`找角色` 位于约 71177 行附近，参数/局部数据包括：

- `找角色:角色`
- `找角色:转换`
- `找角色:I`

结合上层调用，它负责从小地图截图中得到人物标记，并把截图坐标转换到地图节点坐标。人物第一次成功识别后的坐标会经 `存入起点` 写成当前寻路起点；它不是永久固定在某个地图角落。

## 当前判断

程序拼图和导航的核心不是单次识别整张地图，而是：人物移动后反复截取小地图，通过人物位置/移动偏移对齐新区域，把道路颜色形成的可通行节点加入二维数组，再在节点图上搜索从当前人物节点到目标节点的路线。

这解释了为什么脚本中同时存在：截图保持、人物偏移、道路颜色、二维数组、查找列表、找过集合、方向数组和场景切换状态。

## 下一步

从 `libmqm.so` 的 Lua 解释器执行循环恢复 opcode 重排表，然后把字节码转换回标准 Lua 5.2 opcode。完成后 unluac 才能输出接近原始源码的控制流、条件判断和函数调用顺序。
