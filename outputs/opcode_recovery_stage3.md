# Lua opcode 恢复与源码反编译

## 结果

已从 `libmqm.so` 的 `0x4ad200` 指针表恢复 39 个 opcode 名称，并确认字节码使用重排后的 Lua 5.2/5.1 混合指令集。

除了 opcode 编号重排，程序还对全局变量指令做了字段改造：

- 自定义 `GETGLOBAL A,C` 已转换为 Lua 5.2 `GETTABUP A,0,C`
- 自定义 `SETGLOBAL A,C` 已转换为 Lua 5.2 `SETTABUP 0,C,A`

转换器递归遍历每个函数原型，只改写指令字，不改变常量、局部变量、源码行号和函数树。转换后的三个文件已经能够由标准 unluac 反编译。

## 地图坐标连接的真实算法

反编译源码证实 `地图坐标连接(起点, 终点, 地图连接数据)` 是广度优先式图搜索：

1. `查找列表` 初始只包含起点。
2. `找过` 保存已经加入搜索的节点。
3. 地图连接数据每三项构成一条记录：当前节点、该边包含的坐标序列、下一节点。
4. 找到从当前节点出发且尚未访问的下一节点后，将其加入查找列表和找过集合。
5. 同时把边上的坐标序列追加到当前路线字符串。
6. 下一节点等于终点时返回完整路线。

路线以 `-X-Y-X-Y...` 字符串保存。它没有距离权重或启发函数，所以不是 A*。

## 找路函数的新细节

反编译源码显示：

- 根据移动方向使用固定偏移量 `8.71` 和 `17.41` 预测下一位置。
- 人物/节点匹配容差约为 X ±5、Y ±7。
- 小地图有效范围检查包含 X=100–585、Y=200–1150。
- Boss 使用 `CmpColor(..., "3837EC-080808", 1)` 检测红色标记。
- 当前识别坐标在通过障碍点、终点、已找节点等检查后，才会写入本次寻路起点。

## 角色位置与小地图切换

`角色位置` 函数用共享变量 `看小图数` 在四个小地图视角之间循环，并用触控拖动切换视野：

- 计数 1–4 对应四个拖动方向。
- 每次移动后重新截图并调用 `找角色`。
- 超过四次仍未定位时将移动偏移清零并重新开始。
- 定位成功后清空旧数组、记录当前坐标、生成方向数组并进入 `找路`。

因此“起点”不是固定出生点，而是本轮截图中最后一次可靠识别到的人物地图坐标。
